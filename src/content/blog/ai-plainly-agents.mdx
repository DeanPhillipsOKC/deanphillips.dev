This is part 2 of [AI, plainly](/blog/ai-plainly/), and it builds on [part 1's tools](/blog/ai-plainly-tools/).

Say you type one line. Find a dry morning this weekend when the park is open, and draft a text I can send. A few turns later the text is done, and nobody touched it in between.

Here's where my kid-level explanation ran out. Part 1 got the model one request and one result. So how does it do a whole job?

Agents get sold as a smarter kind of AI that keeps thinking in the background. The picture below is what's really there.

## A loop around the loop

<LoopInLoop
  mode="diagram"

An **agent** is the part 0 loop wrapped in a bigger loop. Part 1 called the program around the model the app. In agent talk it's called the **harness**. Claude Code is one (it's what ran my Gesso experiment).

The harness calls the model. The model writes, one token at a time, and sometimes what it writes is a tool request. The harness runs it, pastes the result onto the end, and calls the model again. One model call plus the tool work after it is a **turn**. People call this the agentic loop. (Sometimes the model asks for several tools at once, and the harness runs them together.)

Turn 2 is the one to watch. Nothing in the job said to check Sunday. The model read rain in the conversation and wrote a different request. A script can't do that, because its steps were written before anything came back.

It stops one of two ways. Either it writes an answer with no tool request, so there's nothing left for the harness to do, or the harness stops it (too many turns, too much time or money, or a question only you can answer).

## Its whole memory is the conversation

Between turns, nothing carries over except the text. The harness hands the model the whole conversation again every turn. (There are shortcuts that save work, but they don't change what it sees.)

Think of someone with no memory and a notebook. Each turn they start reading at page one. The harness also slips its own **setup notes** in at the top, which is how the model knew what tools it had in part 1.

The notebook has a page limit, called the **context window**. It's the most text the model can work with at once (counting what it writes). Long jobs fill it.

## A real one, and why checks matter

[Gesso](/blog/gesso-agent-loop/), my ongoing painting-lesson experiment, ran this loop in Claude Code. I wrote the instruction file and its rules, including the checks. Claude ran the lesson alone.

A loop that only makes things will happily make wrong things. That's part 0's confident guesser, now taking actions. So one of Gesso's checks used a fresh copy of Claude with a clean conversation. It caught 2 problems in round 1 and 1 in round 2.

A clean notebook helps because it isn't nudged by the maker's own story. More loops don't check anything by themselves. Someone has to build the check in.

## What's next

Every word the agent writes comes out of the same dials, set during training. That goes for its thinking, its tool requests and its answers alike. Nobody set them by hand.
