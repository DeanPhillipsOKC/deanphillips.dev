This is part 3 of AI, plainly. It builds on [part 1's inference](/blog/ai-plainly/) and [part 2's tools](/blog/ai-plainly-tools/).

Say you type one line. "Find a dry morning this weekend when the park is open, and draft a text I can send." A few turns later the draft text is ready, and you didn't type anything else.

Here's where my kid-level explanation ran out. Part 2 got the model one request and one result. So how does it do a whole job?

Agents get sold as a smarter kind of AI that keeps thinking in the background. The picture below is what's really there.

## A loop around the loop

<AgentLoop caption="One trip around the loop is a turn. Each trip runs inference once, with everything so far." />

An **agent** is inference run in a loop. The model runs, the harness does whatever it asked for, and the model runs again with the result added. It keeps going until the model stops asking for things, or the harness stops it. The program running the loop is the **harness** (part 2 called it the app). Claude Code is one, and it's what ran my Gesso experiment.

Notice what “done” means. The model thinks it's finished. Nothing in the loop checks that the job really got done. More on that at the end.

One trip around is a **turn**. People call this the agentic loop. (Sometimes the model asks for several tools at once. The harness runs them all and pastes every result in before calling it again.)

Turn 2 is the one to watch. Nothing in the job said to check Sunday. A script only follows the branches someone wrote ahead of time, and nobody wrote this one. The model wrote it after reading the result.

It stops one of two ways. Either it writes an answer with no tool request, so there's nothing left for the harness to do, or the harness stops it (too many turns, too much time or money, or it needs your OK first).

## Its whole memory is the conversation

From one model call to the next, nothing carries over except the text. The harness hands the model the whole conversation again every time.

It's the same stack of paper from part 2, now a notebook with a page limit. Each turn the model starts reading at page one. The harness also slips its own **setup notes** in at the top, which is how the model knew what tools it had.

Now picture a bigger job, like planning the whole weekend.

## A real one, and why checks matter

[Gesso](/blog/gesso-agent-loop/) is my ongoing painting-lesson experiment. It takes a photo and makes a step-by-step painting lesson, and every step needs a picture. It ran this loop in Claude Code. I wrote a list of rules for it, including the checks. Claude ran the lesson alone.

A loop that only makes things will happily make wrong things. That's part 1's confident guesser, now taking actions. So one check used a fresh copy of Claude with a clean conversation. It read the lesson and listed problems, Claude fixed them, and another fresh copy read it again.

## What's next

Every word the agent writes comes out of the same dials, set during training. That goes for its thinking, its tool requests and its answers alike. Nobody set them by hand.
