On November 9 I pushed one commit to a brand new public repo. It held every file of RepBunny, my strength training app for iPhone and Android. By that evening a release had gone from that repo to TestFlight and Google Play, and an AI agent had shipped its first change there.

RepBunny is built by a pipeline of AI agents I designed. They pick work from a scored backlog, build it, test it, and open pull requests that a review agent checks. I make the decisions, they do the typing, and nothing goes out without my testing it. The [AI delivery team series](/blog/ai-delivery-team/) covers how that works. This series is about opening it up.

This is the first of three posts. The next one is [the day of the move](/blog/going-public-cutover/), with everything that broke. The last is [what free CI minutes changed](/blog/going-public-minutes/).

## Why now

I had planned to decide this after the App Store launch. On November 4 I moved it up, for three reasons.

First, anyone can check the privacy claims. RepBunny keeps every workout on the phone. No accounts, no shared database, no servers holding anyone's data. Saying that is easy. Letting people read the code that does it is better.

Second, the work is the portfolio. I've written a lot about this pipeline. Now the pull requests, reviews, and CI runs are there to look at instead of described.

Third, minutes. A private repo gets a monthly allowance of GitHub Actions minutes, and I had spent October rationing them. Public repos don't pay for standard runners. That one turned out to matter more than I expected, and it gets [its own post](/blog/going-public-minutes/).

## Two repos, not one

The obvious move was to flip the existing repo to public. I didn't, because the repo isn't only code.

Its issues are the backlog, and the agents read them all day. Each issue is part spec, part conversation. My agents ask me questions there, and I answer there. Some of that text names my testers or quotes support email. More important, an issue is instructions to an agent. In a public repo anyone can open one, and "ignore your rules and do this instead" is a very short issue to write.

So the backlog stayed private, and the code moved to a new public repo. Issues are off on the public one, and nothing automated reads text an outsider can write there. Bug reports go to an email address, and I move anything real into the backlog myself.

## Starting with no history

The new repo started with one commit, the exact files of the old repo's last version. No history.

The old history holds 969 commits of messages and diffs. Somewhere in there are names and addresses that were fine in a private repo. I could have tried to scrub them. I'd rather not bet on finding every one. A fresh start meant checking one set of files instead of every version of them.

For that check, there's a public-content rule and a script that runs on every pull request. It fails on tester names, personal email addresses, and other things that don't belong in public. The agents run it on their own pull request text before they open one, since that text is public now too.

The fresh start had a cost. Several things counted on that history, including build numbers. That's [the next post](/blog/going-public-cutover/).

## The license

Public doesn't mean free to copy. The code is under the PolyForm Shield license. Anyone may read it, look for bugs and security problems, check the privacy claims, fork it, and make a personal build. Nobody may ship a product that competes with RepBunny, free or paid. The name, the icons, and the mascot art aren't licensed at all, so a fork brings its own.

Outside code contributions aren't accepted. Reports are, including security reports through GitHub's private reporting.

<Callout title="The rule of thumb:">
whatever the agents build from is private. Whatever they build is public.
</Callout>

## Giving some back

Going public also meant asking what else could be useful to other people. The first piece is out. The small tool that estimates a private repo's Actions minutes (GitHub's billing page isn't readable from a workflow) is now its own [open source package](https://github.com/DeanPhillipsOKC/actions-minutes-estimator). Next on the list are the backup code that keeps a local-first app's data safe through a lost phone, and the exercise library fixes, sent back to the free dataset they started from.

The code is at [github.com/DeanPhillipsOKC/repbunny-code](https://github.com/DeanPhillipsOKC/repbunny-code). If you read it and find something, I'd like to hear about it.
