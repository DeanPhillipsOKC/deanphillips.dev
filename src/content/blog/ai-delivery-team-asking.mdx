This is part 3 of a series about the AI agents that build RepBunny, a strength training app I work on around a full-time job. The [overview](/blog/ai-delivery-team/) covers the whole setup. This part covers the one place the agents still need me: decisions.

## The ask-the-owner loop

Agents run into decisions they shouldn't make alone: a product tradeoff, a privacy question, a setting only I can change. The first version of this blocked the run and waited for me to show up at the laptop. That made me the bottleneck.

Now they ask on GitHub, in a format I can answer from my phone in ten seconds.

    <li>My phone buzzes. I reply "A" on the issue or straight from the email.</li>
    <li>Another workflow sees the repo owner replied and flips the label to <span class="tag replied">dean-replied</span>.</li>
    <li>The agent that asked picks up the answer and keeps going. For support questions, my reply starts it right away.</li>
  </ol>
</AskOwner>

One rule makes this safe: agents never comment on an issue that's waiting on me. They post as my account, so their comment would look like my answer. They can only ask through the bot.

## Support runs on its own

Support email goes through a `triage-support` skill. It started as something I ran by hand. Now a plain GitHub Actions job checks the support label in Gmail every six hours, read-only, and only starts the agent when something new is waiting. An empty inbox costs nothing.

For each email the agent checks the report against the code, looks for duplicates, and opens a tracking issue with its recommendation and a drafted reply. Then it asks me through the same loop: send the reply and file the fix, send the reply only, or park it. My answer starts the agent right away, and it sends exactly the text I approved. Nothing goes to a customer without my pick.

## What broke

All three of these happened on the first day the support loop ran on its own.

- **The support agent showed up with nothing.** Its first cloud run reported that the skill didn't exist. I'd created the routine without attaching the repo, so there was no code to read. One setting.
- **My phone undid my own answer.** I replied "A" on a question, then removed a label on the same issue in the GitHub app. The app saves labels as a full list, and the screen I edited from was loaded before my reply flipped the label. So it put `awaiting-dean` back and took `dean-replied` off, and the agent decided I hadn't answered. Now the helper counts a comment from me after the question as the answer, whatever the labels say.
- **A builder grabbed a question.** Support tracking issues stayed out of the build lanes only because of one label. I removed it while answering, and twenty minutes later a lane started building the option I was about to turn down. The lanes now skip anything that's a support issue or waiting on me, no matter what other labels it has.

The first was a setting I fixed by hand. The other two became one issue that a lane built, gated, and merged the same day.
