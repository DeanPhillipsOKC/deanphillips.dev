## It writes a note

A **tool** is a helper program the model can ask for, like a web search, a file reader, or a program that runs code. A **tool request** (people call it a tool call) is the note the model writes to ask for one. It isn't a special power. It's more guessed text, in a shape a program can read.

The model doesn't know today's weather. So what's the most useful thing it could write first? Make your guess in the picture.

## A regular program does the work

**The app** is the ordinary program you type into. It runs the model, spots its notes, and hands them to tools. Here's the whole round trip for one question, as a group chat you'd never normally get to see.

Two things are easy to miss. While the tool works, the model isn't waiting. It isn't running at all. When the result comes back, the app runs it again, and it rereads the whole conversation from the top, result included.

And the result is just more text. Nothing checks whether it's true. And if a pasted page says “do this”, the model may do it.

<Callout title="Picture it this way.">
Someone in a closed room who can only pass notes under the door. A helper outside does the errands and slides the answer back. The odd part is that every time a note comes back, the person inside has forgotten everything and rereads the whole stack of paper from the top. (Real systems save their work on the earlier part so they don't redo it. The model still has nothing except what's on the page.)

## Where my first answer was hiding

Web search asks a regular search engine, the same kind you'd use. (Big ones use maps like the one below too, along with matching words.) For your own files and help docs, many tools build their own map. Here's that map.

Ahead of time, a program chops your documents into short pieces called **passages** and gives each one a spot on a map. It's like the word map from the overview, but for whole passages, and it's a separate map. A separate model of its own hands out the spots. In this job it never writes a word. The note the model writes gets a spot too, and the tool grabs the passages sitting nearest to it. That's **retrieval**, the fancy word for finding and fetching.

Searching for the nearest match is real. It's just not how the model answers. It's how many search tools work. The model keeps no copy. The search tool keeps everything, word for word, which is why it can paste real text back.
