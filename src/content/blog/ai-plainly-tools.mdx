## It writes a note

A **tool** is a helper program the model can ask for, like a web search, a file reader, or a code runner. A **tool request** (people call it a tool call) is the note the model writes to ask for one. It isn't a special power. It's more guessed text, in a shape a program can read.

**Guess first.** The model doesn't know today's weather. What's the most useful thing it could write?

How does it know the tools exist? The app around the model (the regular program you're actually typing into) quietly adds a list of them to the conversation. You never see it. (People call hidden instructions like this a system prompt.) And the second round of training from the overview included lots of example conversations where the assistant writes a request and then uses the result.

Two things are easy to miss. While the program works, the model isn't waiting. It isn't running at all. When the result comes back, the app runs it again, and it rereads the whole conversation from the top, result included.

And the result is just more text. The model can't tell a true result from a wrong one, or from a page that tells it what to do.

<Callout title="Picture it this way.">
Someone in a closed room who can only pass notes under the door. A helper outside does the errands and slides the answer back. The odd part is that every time a note comes back, the person inside has forgotten everything and rereads the whole stack of paper from the top.
</Callout>

## Where my first answer was hiding

Back in the overview, my first try at explaining AI went like this.

<QuoteCheck
  head="My first try, graded"

    { text: 'The AI searches through everything it learned from', mark: 'wrong', note: 'Wrong. A search tool searches pages someone stored on purpose. Never the training text.' },
    { text: 'and finds what an answer should look like.', mark: 'close', note: 'Close. A search tool finds the passages nearest in meaning. Then the model still guesses.' },
  ]}

The first half is real. It's just not how the model answers. It's how many search tools work.

Ahead of time, a program chops your documents into short pieces called **passages** and gives each one a spot on a map. It's like the word map from the overview, but for whole passages, and it's a separate map. A small model of its own hands out the spots, and it never guesses words. The note the model writes gets a spot too, and the tool grabs the passages sitting nearest to it. That's **retrieval**, the fancy word for finding and fetching.

That's why it can paste real text back, and it's the part my first try got backwards. The model keeps no copy. The search tool keeps everything. (Sometimes the app runs a search on its own, before the model writes a thing. People call fetch first, then guess RAG, short for retrieval-augmented generation.)

<Callout title="Web search is usually different.">
The tool asks a regular search engine, the same kind you'd use, and pastes back what it finds. Maps like this are common for your own files and help docs. Some systems mix both.
</Callout>

## Why it still gets things wrong

Tools fix the missing fresh facts. They don't fix the guessing. Try the Model 7 question on the map. The closest pages aren't about Model 7, and the answer still comes out smooth. That's the overview's confidently wrong, with better sources.
