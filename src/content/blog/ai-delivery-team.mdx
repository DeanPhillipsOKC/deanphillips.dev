## The short version

RepBunny is a strength training log for iPhone and Android. I'm the only developer. Behind it is a set of AI agents (Claude Code, mostly) that each have one job: turn my rough notes into specs, build the next most valuable issue, test it, ship it, review the app every month, and ask me when something needs a human call.

None of that is one giant prompt. It's about fifteen small skills, a dozen GitHub Actions workflows, and a label scheme on GitHub Issues that every agent reads and writes. The issues are the team's shared memory. If it isn't on an issue, it didn't happen.

## If you want to try this

A few things I'd do again on day one:

1. **Pick one source of truth** and make every agent read and write it. For me that's GitHub Issues and labels. Agents forget everything between runs. The issue tracker doesn't.
2. **Invest in the test suite before the automation.** The gate is what lets you skip code review. Without it, you're just merging faster in the dark. And keep a human between the gate and your users.
3. **Keep the glue dumb.** The dispatcher, emails, and ask-the-owner flow have no AI in them. They're cheap, predictable, and easy to debug.
4. **Write the rules down in the repo.** Every decision I make ends up in a docs file the agents read at the start of each run. That's how a choice I made on Tuesday still holds on Friday.
5. **Plan for yourself as the bottleneck.** The more the agents do, the more your own to-do list becomes the thing everything waits on. Make your part fast and phone-sized, and batch the parts that can't be.
